# ExamPilot admin dashboard

The admin login name defaults to `admin@exampilot.com`. It is a login identifier, not a mailbox; no email is sent. You can override it with the server-only `ADMIN_USERNAME` environment variable.

## 1. Database

In Supabase Dashboard → SQL Editor, run the complete migration:

`supabase/migrations/006_private_usage_analytics.sql`

It creates the private usage-events table with row-level security enabled and no browser-role policies.

## 2. Vercel environment variables

Set these in Project → Settings → Environment Variables:

- `ADMIN_USERNAME` (optional; defaults to `admin@exampilot.com`)
- `ADMIN_PASSWORD`: a long, unique password.
- `ADMIN_SESSION_SECRET`: at least 32 random characters, generated by a password manager.
- `SUPABASE_SERVICE_ROLE_KEY`: server-side service-role key only.
- Existing `NEXT_PUBLIC_SUPABASE_URL` value.

Never commit or share the password, session secret, or service-role key. Redeploy after changing environment variables.

Login: `/admin/login` · Dashboard: `/admin`.

## 3. Rate limiting

Admin login allows five failed attempts per IP in a 15-minute window and applies a 15-minute lockout. Analytics events are limited to 30 requests per IP per minute and 4 KB per payload. The current fallback limiter is in-memory and is therefore best-effort on serverless deployments; separate instances do not share counters. For a public production launch, use a shared Redis/Upstash-compatible limiter.

## 4. Tracking behavior and limits

Students do not need accounts or email verification. With consent, the tracker uses a random browser ID and the name/branch/semester from the local academic profile, if present. It records feature/page visits and timestamps—not passwords, notes, or AI chat content.

This identifies a browser, not a verified person. Clearing browser storage or using another device creates a different visitor. Visitors without an academic profile appear anonymous. Keep the privacy notice visible and respect a visitor's choice to decline.
